# KayaGo · 围棋 AI 对弈

一个**开源、零第三方依赖**的 Android 围棋应用，内置**从零实现的蒙特卡洛树搜索（MCTS）AI**。
不联网、不加载任何权重文件，装上就能下。

> 榧（kaya）是传统日本棋盘的用材，项目名由此而来。

---

## 下载安装

到本仓库的 [Releases](../../releases) 页面下载 `KayaGo-1.0.0.apk`，手机上打开安装即可
（需要允许「安装未知来源应用」）。

- 最低系统：Android 8.0（API 26）
- 目标系统：Android 14（API 34）
- 安装包体积：约 70 KB

## 棋力说明（请先读）

本项目的 AI 是**从零手写的传统 MCTS 引擎**，没有神经网络、没有人类棋谱训练、没有权重文件。
请对棋力有合理预期：

- **9 路**：大约相当于业余级位水平——初学者到入门爱好者可以一战。
- **13 / 19 路**：搜索空间大得多、推演更短，棋力明显弱于 9 路，适合休闲对弈。
- 它**不是** KataGo / Leela Zero 那种职业级引擎，本项目也不追求那条技术路线。
  如果你要的是「最强」，请直接使用 KataGo。

引擎擅长的事情：吃子、打吃逃跑、做眼/破眼的基本判断、局部应手、开局占角、
收官时不去填自己的空。
不擅长：大规模全局战斗、精确的形势判断、复杂的劫争转换。

> 想让它更强：直接调高「AI 棋力」档位（思考时间越长越强）。

## 技术实现

### 1. 规则内核 `com.kayago.game`

- **`Board`**：棋盘状态 + 增量维护的棋块结构。
  - 坐标用「带边框」内部索引，边界统一为 `WALL`，省掉所有越界判断。
  - 棋块用**单向链表**表示，链头索引即棋块 id；气数用「时间戳去重」统计，
    落子 / 撤销都在 O(棋块大小) 量级。
  - 提子时相邻敌块气数直接 **-1**（落子点原本就是它们的口气），避免反复全量扫描；
    只有自己这块棋在落子后重算一次气数。
  - 撤销时需要处理「接点被摘掉导致棋块裂开」的问题：只有在落子时**合并了 2 块以上**
    己方棋的情况下才做一次连通性检查，必要时按相邻关系局部重建棋块。
  - **位置超级劫**：用开放寻址的长整型哈希集合记录本局出现过的所有局面，
    既保证规则正确，也让 AI 在搜索中不会提出重复局面的着法。
- **`Scorer`**：中国规则数子（子 + 空），并输出每个空点的归属图供界面显示。
- **`Game`**：对局流程、历史、终局判定、认输。

### 2. AI 引擎 `com.kayago.ai`

- **共享树多线程 UCT**：节点访问数 / 胜场用原子量维护，选择时叠加 virtual loss 降低线程撞车。
- **根节点 PUCT + 启发式先验**（棋力关键）：纯 UCT 在空盘、稀疏局面下胜率几乎是纯噪声，
  引擎会随手走废棋。这里先把每个合法点做一次棋理打分（提子、救棋、自紧气、连络、
  线位、与前手距离、角部常见着点……），再用 softmax 变成先验分布，按
  `Q + c·P·√N/(1+n)` 选择。开局因此会自然地占角（三三/星位），而不是贴着边线乱走。
- **根节点 RAVE / AMAF**：把「本局快速推演里出现过、且落在窗口内」的着法也算作一次访问，
  用 `β = √(k/(3n+k))` 与树内胜率混合。访问次数还很少时，这个信号比树内胜率可靠得多。
- **轻量推演策略**：一次邻居扫描完成大部分判断——能提就提、被打吃就逃、
  不填自己的眼、不自紧气、不往自己空里填、优先在上一手附近应。
- **终局**：双方连续停手或达到步数上限后，用中国规则数子判断胜负。
- **形势判断**：`estimateScore` 只做随机推演不建树，用来估算领先子数。

性能量级（开发机 JVM，单线程）：约 **0.5 ~ 1 万局随机推演/秒**（视局面而定），
`play + undo` 约 **150 万次/秒**。手机上按 CPU 核心数并行（最多 8 线程）。

仓库里还带了一个对局跑分工具 `tools/MatchRunner.java`：让同一套代码的两组搜索配置
互相对弈（每局交换黑白），用来客观检验某项改动到底有没有让引擎变强，而不是凭感觉。

### 3. 界面 `com.kayago.ui`

- **`BoardView`**：完全自绘——木纹渐变棋盘、三层柔和阴影、立体棋子（径向渐变 + 投影 + 高光）、
  星位、坐标（跳过字母 I）、最后一手标记、待确认落点、AI 建议金环、归属标记；
  落子有 140ms 缩放淡入动画与触感反馈；处理两步确认落子。
- **`PlayerCardView`**：黑/白棋手卡片（立体棋子图标、我方/AI、执子、提子数），
  行棋方高亮，AI 思考时显示进度条。
- **`ActionButton`**：底部图标操作按钮（自绘 vector 图标 + 文字标签）。
- **`MainActivity`**：对局状态机、三个自定义对话框（新对局设置 / 形势判断 / 终局结算）、
  AI 后台线程与状态令牌。`onDraw` 内不做对象分配，着色器只在几何变化时重建。

## 项目结构

```
app/src/main/java/com/kayago/
├── game/         规则内核（纯 Java，可在 JVM 上直接测试）
│   ├── Board.java      棋盘、棋块、气、提子、劫、超级劫、撤销
│   ├── Scorer.java     中国规则数子 + 归属图
│   └── Game.java       对局流程
├── ai/           AI 引擎（纯 Java）
│   ├── GoAI.java       引擎接口
│   ├── MctsEngine.java MCTS 搜索（PUCT 先验 + RAVE + virtual loss）
│   ├── Playout.java    推演策略
│   ├── HeuristicPolicy.java 启发式走子评估
│   ├── SearchConfig.java / SearchResult.java
└── ui/           界面
    ├── BoardView.java       自绘棋盘
    ├── PlayerCardView.java  棋手卡片
    ├── StoneView.java       立体棋子图标
    ├── ActionButton.java    底部操作按钮
    └── MainActivity.java    对局流程与对话框
tools/EngineSelfTest.java   规则/引擎自测（不参与 APK 打包）
tools/MatchRunner.java      自对弈跑分，用于验证引擎改动
```

## 构建

依赖：JDK 17+、Android SDK（platform 34、build-tools 34）。

```bash
# 指向你的 Android SDK
echo "sdk.dir=/path/to/android-sdk" > local.properties

# 打包
./gradlew assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
```

仓库内自带一个**演示用签名**（`keystore/kayago-release.jks`，
storePassword / keyPassword 均为 `kayago2026`，alias `kayago`），
这样任何人都能得到一个可直接安装的包；**要上架应用商店请务必换成你自己的 keystore。**

## 自测

规则内核和 AI 都是纯 Java、零 Android 依赖，可以直接在电脑上跑：

```bash
javac -encoding UTF-8 -d /tmp/kayago-test \
  app/src/main/java/com/kayago/game/*.java \
  app/src/main/java/com/kayago/ai/*.java \
  tools/EngineSelfTest.java
java -cp /tmp/kayago-test tools.EngineSelfTest
```

覆盖 53 项断言：单子提子、禁止自杀、「先提子后有气」、
简单劫与位置超级劫、真假眼识别、数子与归属、随机落子 + 逆序撤销的一致性压力测试、
开局不乱走一路二路、形势判断方向、AI 能否吃掉被打吃的大龙、AI 自对弈完整性。

引擎改动是否真的变强，不看感觉看跑分：

```bash
java -cp /tmp/kayago-test tools.MatchRunner 16 150 9     # 每手 150ms，9 路，16 局
```

它会让同一套代码的两组配置互相对弈、每局交换黑白，输出胜率。
1.1.0 的实测结果：当前引擎（PUCT 先验 + RAVE + 分差回报）对旧版纯 UCB1 引擎
**12 : 4（75%）**。

## 已知限制

- 棋力有限（见上文），19 路偏弱。
- 没有让子（handicap）设置，没有棋谱保存 / SGF 导入导出。
- 没有做多线程搜索的结果复现（搜索本身带随机性）。
